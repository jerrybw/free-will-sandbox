# 中性占位主题「源质工坊」— 第二阶段开发规格（v2，替代已撤回的甜酒方案）

> 主题暂未定调。本阶段目标：用中性占位主题把核心循环跑通，**配置化架构优先**——所有文案/数值外置 JSON，主人定调主题后只改配置不改代码。
> 旧甜酒规格作废。Mock 规范（第十节）继续有效。

## 一、占位主题与基调
- **占位主题：源质工坊（Essence Workshop）**——抽象的能量采集/合成场景：采集「源质」与「晶核」，合成「聚合体」，升级工具与自动化。不绑定任何具体题材
- UI 简洁中性：深蓝灰底 + 单一强调色（现有深色风格微调即可），圆角卡片，无强题材元素
- 严禁血腥、暴力、色情内容

## 二、核心架构要求（本阶段最高优先级）
1. **文案 100% 外置**：所有用户可见文本（页面标题、面板标题、按钮文字、资源名、动作名、升级名/描述、事件文案、里程碑文案、日志模板、空状态提示）全部进 JSON。代码中零硬编码主题词
   - 建议结构：`src/config/` 下按域拆分 `game-config.json`（资源/动作/升级/事件/里程碑数值）+ `ui-texts.json`（全部界面文案），经 `src/game/config.ts` 汇聚导出
   - 换主题验收标准：只改两个 JSON 文件，游戏即变成另一题材，无需动任何 .ts/.html/.css
2. **数值全部配置驱动**：产出量、升级费用与成长系数、事件概率与效果、里程碑阈值，全部 JSON
3. 现有分层保持：config / types / game（store、game + 新增 events.ts、milestones.ts）/ ui/render

## 三、资源与动作（JSON 配置，占位命名）
| id | 名称 | 获取 |
|----|------|------|
| essence | 源质 ✨ | 点击「采集源质」 |
| core | 晶核 💠 | 点击「萃取晶核」 |
| composite | 聚合体 🔷 | 合成产出（消耗源质+晶核） |

- 点击动作：采集源质（+2 essence）、萃取晶核（+1 core）
- 合成动作：合成聚合体（消耗 源质10+晶核2 → 1 composite）——首个"转换型"动作，验证配置可表达消耗型动作

## 四、事件系统（新增 events 模块，JSON 配置）
- 随机事件池示例（文案+参数全配置）：
  - 流星雨：10s 内点击产出 ×2（触发概率、持续时长、倍率、文案均配置）
  - 能量潮汐：一次性 +20 源质
  - 共振：下 3 次合成免消耗晶核
- 实现：tick 内按概率触发 → toast/日志提示 → 计时生效/结算；效果作用器用简单枚举（multiplier_click / grant_resource / free_cost_n）映射，新效果类型可扩展
- 事件进行中有轻量指示（顶栏小徽标或倒计时条）

## 五、进度系统（新增 milestones 模块，JSON 配置）
- 里程碑示例：累计采集 100/500/2000 源质、首次合成、拥有 5 个升级 → 各给徽章/称号+一次性奖励
- UI：进度面板小节，展示已完成/下一目标；文案全配置

## 六、升级体系（JSON 配置，扩到 8-10 项）
- 聚能镐（采集源质 +1/级）、晶核切割器（萃取 +1/级）
- 汇聚环（每 tick 自动 +1 源质）、共振塔（每 tick 自动 +0.5 晶核→实现为每 2 tick +1）
- 合成优化（合成消耗 -10%/级，上限 50%）
- 自动合成器（每 tick 自动尝试合成，消耗充足时执行）
- 仓储扩容（资源上限 +500/级，引入软上限验证可扩展性）
- 费用成长：每级 ×1.6（系数配置）

## 七、UI 布局（简洁中性）
- 顶栏：标题（文案来自配置）+ 资源栏（含每秒速率）+ 活动事件徽标
- 左栏：采集区（点击/合成按钮）
- 中栏：升级商店（卡片网格）
- 右栏：事件动态 + 里程碑进度 + 日志
- 顶栏导航保留「游戏 / 开发进度」

## 八、技术要求
1. 存档 SAVE_KEY 升 v2：新增事件状态/里程碑/累计统计字段；v1 档安全迁移（缺省合并初始值），不崩溃
2. `npx tsc --noEmit` 0 error；`npx vite build` 成功；JS+CSS gzip 合计 < 15KB
3. tick 渲染无卡顿（60fps）

## 九、验收标准
- 全流程可玩：点击采集 → 合成 → 买升级 → 事件触发生效 → 里程碑达成提示
- **换主题演练**：临时把 JSON 文案改成任意另一题材（如海洋），验证游戏完全正常 → 验证后改回占位文案
- 刷新页面：资源、升级、事件中状态、里程碑恢复
- 无安全红线内容；性能预算内

## 十、Mock 优先规范（主人指令，必须执行；由并行任务实施进度页部分）

1. **代码层**：Mock 处统一注释 `// [MOCK]`，写清将来替换的真实实现
2. **数据层**：Mock 数据集中放 `public/data/mock/*.json`，与游戏配置（src/config/）物理分开
3. **UI 层**：展示 Mock 数据的区域加「Mock」角标
4. **交付汇报**：分「真实现清单」「Mock 清单」

Mock 范围：进度页 Issues 数据 / 通知记录 / 黑名单拦截 / 需求表单提交流转 / PR 发布状态（均 Mock，将来接 GitHub API / 边缘函数）
